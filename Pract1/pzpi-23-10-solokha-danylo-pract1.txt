3 ОПИС ВИКОНАНОЇ РОБОТИ

3.1 Загальні відомості про шаблони (патерни) проєктування

     Шаблони проєктування (Design Patterns) - це типові, перевірені рішення поширених проблем, які виникають під час розробки програмного забезпечення. Вони не є готовим кодом, а описують загальний підхід до організації структури та взаємодії об'єктів, що дозволяє розробникам ефективніше вирішувати повторювані завдання. Застосування патернів допомагає стандартизувати підходи до програмування, зменшити кількість помилок, підвищити зрозумілість коду та спростити його масштабування і підтримку.

3.2 Опис обраного патерна

Назва патерна: Прототип (Prototype)
Тип шаблона (патерна): породжувальний
Основне призначення:
Патерн Prototype дозволяє копіювати об'єкти, не залежачи від їхніх конкретних класів. Об'єкт сам відповідає за своє копіювання - для цього він реалізує інтерфейс із методом клонування. Це вирішує дві реальні проблеми: по-перше, зовнішній код не може скопіювати приватні поля об'єкта, бо вони недоступні ззовні; по-друге, для копіювання об'єкта через загальний інтерфейс не можна прив'язатися до конкретного класу, якщо він невідомий. Патерн усуває обидві проблеми: об'єкт сам читає свої приватні поля і повертає готову копію через спільний інтерфейс клонування.
Передумови застосування:
1. Коли код не повинен залежати від конкретних класів об'єктів, які він копіює. Таке трапляється, коли об'єкти передаються через абстрактний інтерфейс і конкретний клас за ним невідомий. Prototype дозволяє клонувати такі об'єкти без прив'язки до їхніх класів.
2. Коли в системі є велика кількість підкласів, які відрізняються лише початковими значеннями полів. Замість того, щоб заводити окремий підклас під кожну конфігурацію, можна тримати набір налаштованих прототипів і клонувати потрібний.
3. Коли створення об'єкта є дорогою операцією - вимагає складних розрахунків, звернення до бази даних або завантаження зовнішніх ресурсів. У такому випадку клонування вже ініціалізованого прототипу значно ефективніше, ніж повне створення об'єкта з нуля.

Переваги:
1. Незалежність від конкретних класів. Клієнтський код прив'язаний лише до інтерфейсу клонування, а не до деталей реалізації конкретних класів. Це підвищує гнучкість системи та спрощує її розширення.
2. Зменшення дублювання коду ініціалізації. Логіка налаштування об'єкта зосереджена в прототипі, а не розсипана по всьому коду. Клієнт просто клонує готовий об'єкт замість того, щоб щоразу конструювати його з нуля.
3. Підвищення швидкості створення об'єктів. Клонування, як правило, швидше за повне створення об'єкта, особливо якщо ініціалізація потребує дорогих операцій.
4. Альтернатива підкласам. Замість N підкласів для N різних конфігурацій можна мати N прототипів у реєстрі, що зменшує кількість класів у системі та знижує її складність.

Недоліки:
Складність глибокого копіювання. Якщо об'єкт містить посилання на інші об'єкти, необхідно вирішити: виконати поверхневе копіювання (shallow copy), що залишає спільні посилання між оригіналом і копією, або глибоке (deep copy), що вимагає рекурсивного обходу всього графа об'єктів. Якщо в графі є циклічні залежності, реалізація глибокого копіювання стає нетривіальною задачею.


3.3 Структура шаблона (патерна)
Опис структурних частин:
1. Prototype (інтерфейс прототипу) - оголошує метод або методи клонування. Забезпечує спільний контракт, через який клієнт взаємодіє з усіма об'єктами, що підтримують копіювання, незалежно від їхніх конкретних класів.
2. ConcretePrototype (конкретний прототип) - реалізує операцію клонування. Всередині методу створюється новий об'єкт поточного класу і в нього копіюються всі поля, включно з приватними. Якщо об'єкт містить вкладені об'єкти - тут вирішується питання глибокого копіювання.
3. Client (клієнт) - ініціює клонування через інтерфейс Prototype. Не знає і не залежить від конкретного класу об'єкта, що клонується.
4. PrototypeRegistry (реєстр прототипів, опціонально) - зберігає набір налаштованих прототипів у вигляді хеш-таблиці "ім'я → об'єкт". Клієнт вказує ключ, реєстр повертає клон потрібного прототипу.
Опис взаємодії об'єктів:
1. Client звертається до об'єкта через інтерфейс Prototype і викликає метод clone(). Клієнт не знає конкретного класу об'єкта.
2. ConcretePrototype отримує виклик clone() і самостійно створює нову копію свого стану. Якщо є ієрархія класів - підклас викликає конструктор або метод батька для копіювання успадкованих полів, а сам копіює власні поля.
3. Client отримує готовий клон через інтерфейс Prototype і працює з ним, не знаючи деталей реалізації.
4. Якщо використовується PrototypeRegistry - клієнт звертається до реєстру за ключем, реєстр знаходить потрібний прототип і повертає його клон. Прямих викликів конструктора в клієнтському коді немає.

3.4 Реалізація шаблона (патерна)

Основні етапи:
1. Створення базових інтерфейсів
Prototype - інтерфейс, що оголошує метод clone(). Всі класи, які підтримують клонування, реалізують цей інтерфейс. Завдяки цьому клієнтський код може викликати clone() на будь-якому об'єкті, не знаючи його конкретного класу.
Shape - абстрактний базовий клас для ієрархії геометричних фігур. Реалізує інтерфейс Prototype і містить конструктор-прототип, який приймає об'єкт свого класу та копіює з нього всі поля. Метод clone() оголошений абстрактним - кожен підклас зобов'язаний перевизначити його самостійно, інакше при клонуванні буде повернуто об'єкт батьківського класу.
2. Реалізація конкретних класів
Circle та Rectangle - конкретні підкласи Shape. Кожен додає власні поля (radius, width, height) і реалізує clone(): повертає new Circle(this) або new Rectangle(this). Конструктор підкласу викликає super(source), щоб батьківський клас скопіював спільні поля (x, y, color). Підклас копіює лише свої власні поля. Таким чином, кожен рівень ієрархії відповідає тільки за своє.
3. Демонстрація використання
Клієнтський код працює з масивом об'єктів типу Prototype. Що конкретно там зберігається - Circle, Rectangle чи інша фігура - клієнту невідомо. Виклик clone() на кожному елементі завдяки поліморфізму автоматично запускає правильну реалізацію. У результаті отримуємо точні копії всіх об'єктів без прив'язки до жодного конкретного класу.

Зпит до ШІ
Створи приклад на C#, що реалізує патерн Prototype для HTTP-запитів.
Вимоги:
* Клас запиту з полями: URL, токен, словник параметрів 
* Метод Clone() з копіюванням словника (deep copy) 
* Методи для створення змінених копій (наприклад зміна токена або додавання параметра) 
* Використання HttpClient для виконання GET-запиту 
* Формування query string з параметрів 
* Асинхронне виконання запитів 
* У Main створити базовий об'єкт і кілька його копій з різними значеннями 
* Виконати всі запити паралельно 

Приклад прогрманого коду
using System;
using System.Collections.Generic;
using System.Linq;
using System.Net.Http;
using System.Threading.Tasks;

class HttpRequest
{
    public string Url { get; set; }
    public string Token { get; set; }
    public Dictionary<string, string> Parameters { get; set; }

    public HttpRequest(string url, string token)
    {
        Url = url;
        Token = token;
        Parameters = new Dictionary<string, string>();
    }

    // Deep copy clone
    public HttpRequest Clone()
    {
        var clone = new HttpRequest(Url, Token);
        clone.Parameters = new Dictionary<string, string>(Parameters);
        return clone;
    }

    // Методи для створення змінених копій
    public HttpRequest WithToken(string newToken)
    {
        var clone = Clone();
        clone.Token = newToken;
        return clone;
    }

    public HttpRequest AddParameter(string key, string value)
    {
        var clone = Clone();
        clone.Parameters[key] = value;
        return clone;
    }

    // Формування query string
    private string BuildQueryString()
    {
        return Parameters.Count == 0 ? "" : "?" + 
            string.Join("&", Parameters.Select(p => 
                $"{p.Key}={Uri.EscapeDataString(p.Value)}"));
    }

    // Виконання GET-запиту
    public async Task<string> ExecuteAsync()
    {
        using var client = new HttpClient();
        client.DefaultRequestHeaders.Add("Authorization", $"Bearer {Token}");
        try
        {
            var response = await client.GetAsync(Url + BuildQueryString());
            return $"[{Token}] {response.StatusCode}";
        }
        catch (Exception ex)
        {
            return $"[{Token}] Error: {ex.Message}";
        }
    }
}

class Program
{
    static async Task Main()
    {
        // Базовий об'єкт з параметрами
        var baseRequest = new HttpRequest("https://api.github.com/users", "token_base");
        baseRequest.Parameters["per_page"] = "10";

        // Копії з різними токенами та параметрами
        var request1 = baseRequest.WithToken("token_user1").AddParameter("since", "1");
        var request2 = baseRequest.WithToken("token_user2").AddParameter("since", "100");
        var request3 = baseRequest.WithToken("token_user3").AddParameter("since", "200");

        // Паралельне виконання запитів
        var results = await Task.WhenAll(
            request1.ExecuteAsync(),
            request2.ExecuteAsync(),
            request3.ExecuteAsync()
        );

        foreach (var result in results)
            Console.WriteLine(result);
    }
}
